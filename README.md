# instrument-bridge

用现实乐器的声音控制游戏里的虚拟乐器。

目前实现了：**木吉他（麦克风）→ 《异环》钢琴**。

```
麦克风采集 → YIN 音高检测 → 八度修正 → 起音判定 → 整体移调 → 游戏键位 → 发送按键
```

| G3 | G5 | `G` |

## 怎么用

有两种方式。**只想用的话选方式一；想改代码选方式二。**

### 方式一：独立 exe（不用装 Python）

1. 双击 `instrument-bridge.exe`
2. 游戏里**打开钢琴界面**
3. 黑窗口出现后，**鼠标点一下游戏窗口**（让游戏获得焦点）
4. **手离开鼠标键盘，开始弹**
5. 按 `Ctrl+C` 退出

exe 就在仓库的 [`release/instrument-bridge.exe`](release/instrument-bridge.exe)，约 21 MB，直接下载双击即可。也可以自己打包（见文末「打包成 exe」）。

### 方式二：源码 + 一键安装

需要电脑上装了 **Python 3.10 或更新**（[下载](https://www.python.org/downloads/)，安装时**务必勾选 "Add Python to PATH"**）。

1. 解压项目到任意位置（路径**不要有中文和空格**）
2. 双击 **`一键安装.bat`**，等它跑完显示 `Done.`
3. 之后双击 **`弹琴.bat`**，然后同样是上面的第 2~5 步

> 如果 pip 下载卡住，用它提示的清华镜像命令重跑一次。

### 两种方式的区别

| | 独立 exe | 源码 |
|---|---|---|
| 需要装 Python | ❌ 不用 | ✅ 要 |
| 体积 | 约 21 MB | 50 KB |
| 能用辅助工具 | 只有主程序 | 全部（麦克风测试、校准、建表向导） |
| 适合谁 | 只想用的人 | 想调参、换游戏、改代码的人 |

### 第一次用，先测麦克风

**源码版**：双击 `麦克风测试.bat`，对着麦克风说话看条子动不动，再弹几下吉他，记下两个数：

- 安静时的底噪（一般 -70 左右）
- 弹琴时的电平（一般 -20 ~ -35）

两者差 20dB 以上才稳。差得不够，就调 `--gate-db`（见下面的参数表）。

### ⚠️ 必须注意

- **钢琴界面没打开时不要运行程序** —— 按键会变成普通游戏操作，可能开菜单、用道具
- **游戏窗口必须是前台窗口**，不是前台就收不到按键（`PostMessage` 也绕不过这个检查）
- 能干净映射的音域是**吉他 C3 ~ B3**，超出会折叠跳变
- 麦克风是这套方案最弱的一环。头戴麦拾取木吉他信噪比差，有条件的建议用压电拾音器

## 工作原理

### 1. 音高检测：YIN

用 [YIN](https://doi.org/10.1006/jpho.2001.0147) 算法，不是简单的 FFT 取峰。

因为吉他单音的谐波（2 次、3 次）经常比基频还强，FFT 取峰会把八度听错。YIN 的累积均值归一化差异函数在结构上就是为了压制倍频错误。

### 2. 八度修正

YIN 有个固有弱点：周期为 T 的信号，周期也是 2T。所以它偶尔会踩进 2T，报出来的频率只有真实值的一半——**听感上低一个八度**。

修正方法是**频谱交叉验证**，判据是奇次谐波：

- 真实基频 `f0`：谐波在 `f0, 2f0, 3f0, 4f0...` 都有，**`3f0` 有能量**
- 次谐波错误（真基频是 `2f0`）：能量在 `2f0, 4f0, 6f0`，而 `3f0` 相当于真基频的 1.5 倍，**那里是空的**

所以只有当 `3f0` 明显弱于 `2f0` 和 `4f0` 时，才判定报低了，乘 2。

> 早期版本用"2 倍频比基频强就翻倍"，会在高音弦上误伤——吉他高音弦的基频本来就可能弱于二次谐波。详见 `src/pitch.py`。

### 3. 起音门控

不是"音高一变就触发",而是检测**电平突变**（比最近低点高 8dB 以上）。

这样吉他一个音在衰减过程中，算法飘到泛音上也不会冒出假音符。

### 4. 整体移调

**移调必须是 12 的整数倍**，否则整首曲子的调性会变。

| `--transpose` | 吉他 C3 落到 |
|---|---|
| +12 | 低音区 C4（`Z`） |
| **+24** | **中音区 C5（`A`）** ← 默认 |
| +36 | 高音区 C6（`Q`） |

### 5. 按键注入

用 `PostMessageW` 往游戏窗口的消息队列塞 `WM_KEYDOWN`/`WM_KEYUP`，带硬件扫描码。

比 `SendInput` 好：不需要抢系统输入焦点。但**游戏窗口必须在前台**——异环会检查焦点，不是前台就丢按键。

## 换一个游戏：建表向导

内置的键位表只有《异环》。换游戏用向导自己生成：

```bash
.venv\Scripts\python.exe setup_wizard.py
```

或者双击 `建表向导.bat`。

流程：

1. 输入游戏窗口标题（找不到可以试带尾随空格的，用引号包住）
2. 确认按键布局（默认三排各 7 键：`QWERTYU / ASDFGHJ / ZXCVBNM`）
3. 逐个按键，听游戏发出什么音，输入音名（支持 `C4` / `D#3` / `Db3` / `60`）
4. 选黑键规则（Shift+下方白键 / Ctrl+上方白键 / 跳过）
5. 自动生成 `profiles/games/<名字>.json`

然后：

```bash
.venv\Scripts\python.exe live_to_game.py --profile profiles/games/你的游戏.json
```

> 窗口标题的坑：Windows 的窗口标题**可能带尾随空格**。《异环》的真游戏窗口是 `"异环  "`（两个空格），而 `"NTEGame"` 是启动器——发错了没反应。找不到窗口时把标题用引号包起来可以保留空格。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--device` | 自动 | 输入设备编号。不填会自动挑 WASAPI 设备 |
| `--low-latency` | 关 | 窗口减半（43ms→21ms），音域下限提到 110Hz |
| `--transpose` | 24 | 整体移调，**必须是 12 的倍数** |
| `--gate-db` | -38 | 静音门限（dBFS）。环境吵就调高 |
| `--min-conf` | 0.65 | 最低置信度。调高更严格但会漏音 |
| `--stable` | 2 | 连续几帧一致才认。调高更稳但更迟钝 |
| `--onset-db` | 8 | 起音判定灵敏度 |
| `--hold` | 0.03 | 按键按住秒数 |
| `--dry-run` | — | 只打印不发送，用来调试 |
| `--verbose` | — | 每帧打印检测细节 |

### 门限怎么调

1. 跑 `麦克风测试.bat`，看安静时的底噪
2. 弹琴，看弹奏时的电平
3. 门限取两者中间，偏上一点

参考：安静房间底噪约 -75 dBFS，吉他约 -20 ~ -35 dBFS，门限设 -45 比较合适。

## 开发中的坑（技术笔记）

**1. YIN 会把 E4 判成 E3**
信号在 T 和 2T 处都有低谷。用频谱奇次谐波判据修正，见上文。

**2. "2 倍频更强就翻倍"会误伤高音**
高音弦基频本来就弱于二次谐波。修正判据必须看奇次谐波。

**3. 移调必须是 12 的倍数**
`+17` 不是"高一点"，是把整首曲子从 C 调变成 F 调。

**4. 逐音折叠会造成音高断裂**
"低于音域下限就翻八度"会在边界处产生断崖，旋律乱跳。必须整体移调，只对极少数超范围音做回退折叠。

**5. 游戏只认前台窗口**
`PostMessage` 也绕不过游戏的焦点检查。必须让游戏在前台。

**6. 短窗口的代价**
窗口从 2048 减到 1024 延迟减半，但自适应门限会因安静帧 RMS 更低而误判。目前用固定门限。

**7. Windows 控制台是 GBK**
输出含 `¢` 等字符会直接崩，需要 `errors="replace"` 兜底。

**8. .bat 文件必须是 CRLF 换行**
写成 LF 的话，cmd 会逐字节错读，双击后**闪一下就退出**，还可能在命令行里乱执行东西。
更坑的是：用某些编辑器/脚本生成 `.bat` 时默认给 LF，在 Linux/macOS 上完全正常的同一份内容，到 Windows 就炸。

**9. 用 ASCII 编码写 .bat，中文会变成问号**
`[System.Text.Encoding]::ASCII` 只能存 0-127。要显示中文得用 UTF-8 + `chcp 65001`，但 cmd 解析 UTF-8 批处理本身有坑——所以最稳的做法是**批处理内容全用英文**，中文只出现在文件名里。

## 已知限制

- **延迟**：低延迟模式约 21ms 窗口，加上采集和游戏处理，仍有可感延迟
- **音域不匹配**：吉他 3.5 个八度，游戏 3 个八度，只有 C3~B3 能干净映射
- **只能单音**：游戏钢琴是单音的，扫弦只会出一个音
- **麦克风质量**：头戴式麦克风拾取木吉他信噪比差，建议用压电拾音器
- **只支持有起音的乐器**：触发逻辑基于电平突变，适合拨弦/敲击类。笛子、二胡、人声这类持续音需要改成音高变化触发（未实现）

## 兼容性与冲突排查

### 这个程序到底碰了什么

它只调用这些系统 API：

| 类别 | API | 作用 |
|---|---|---|
| 窗口 | `FindWindowW` | 按标题找窗口 |
| 窗口 | `GetForegroundWindow` / `IsIconic` | 查询窗口状态（只读） |
| 窗口 | `ShowWindow` | **仅在窗口最小化时**恢复 |
| 窗口 | `SetForegroundWindow` | 把窗口切到前台 |
| 窗口 | `SendMessageW` / `PostMessageW` | 发按键消息 |
| 键盘 | `MapVirtualKeyW` | 虚拟键码转扫描码 |
| 音频 | `sounddevice` → PortAudio | 采集麦克风 |

**没有涉及**：显卡、驱动安装、显示设置、注册表写入、系统服务、管理员权限。

### 运行前先自检

```bash
.venv\Scripts\python.exe check_env.py
```

会输出：系统版本、显示适配器、所有音频输入设备、可能冲突的软件、当前窗口列表。

**只读，不修改任何东西，不需要管理员权限。** 跑一遍能提前发现大部分环境问题。

### 常见冲突软件

| 软件 | 可能的问题 | 建议 |
|---|---|---|
| 安卓模拟器（MuMu / 夜神 / 雷电） | 会安装虚拟显示适配器；可能抢输入 | 不用时关掉 |
| 远程 / 串流（Parsec / Sunshine / ToDesk / 向日葵） | 抢焦点、切换显示模式 | 游戏时关闭 |
| 反作弊（EAC / BattlEye / Vanguard） | 可能拦截合成输入 | 本程序只发窗口消息，但仍有风险 |
| 输入法 | 中文输入法可能吞掉按键 | 切到英文输入法 |
| 外设软件（雷蛇 / 罗技） | 宏按键可能冲突 | 关闭宏 |

### 如果出现显卡 / 显示异常

**本程序不访问显卡。** 如果运行后出现显卡消失、分辨率异常、显示设置被改，按这个顺序排查：

1. **设备管理器 → 显示适配器** —— 看显卡还在不在，有没有黄色感叹号
2. 有感叹号就双击看**错误代码**（`Code 43` = 驱动崩溃，最常见）
3. **事件查看器**（`eventvwr.msc`）→ Windows 日志 → 系统 → 筛选 `nvlddmkm` 或 `Display`
4. 处理顺序：重启 → 重装显卡驱动 → 检查电源和散热

这类问题通常是驱动崩溃或硬件原因。跟一个只发键盘消息的 Python 程序没有因果关系，但时间上可能碰巧重合——所以上面给了排查步骤，而不是让你只能猜。

### 全屏还是窗口化

程序**不会**改变游戏的全屏/窗口化状态。

但如果游戏用的是**独占全屏**，窗口消息可能根本收不到，按键没反应。遇到这种情况改成**无边框窗口化**。

## 其他乐器能适配吗

代码本身是通用的（YIN 和音名换算与乐器无关），变的只是参数：

| 乐器 | 能用吗 | 要调什么 |
|---|---|---|
| 尤克里里 / 曼陀林 | ✅ | 只调音域 |
| 口琴 / 竖笛 / 笛子 | ⚠️ | 需要换触发模式（持续音） |
| 二胡 / 小提琴 | ⚠️ | 触发模式 + 滑音去抖 |
| 人声 | ⚠️ | 颤音平滑 |
| 钢琴单音 | ✅ | 只能弹单音 |
